## 2. 실행과 시험 (PowerShell)

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest tests -q
$env:SQLITE_PATH = "data/dev_local.sqlite3"   # 저장소에 커밋된 DB를 쓰지 않으려면
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

뉴스 수집(네트워크가 되는 PC에서):

```powershell
.\.venv\Scripts\python.exe scripts\collect_news.py --check   # 출처가 열리고 파싱되는지만 점검(저장 안 함)
.\.venv\Scripts\python.exe scripts\collect_news.py           # 수집·요약·저장
```
매일 06:00(KST) 실행은 Windows 작업 스케줄러에 위 명령을 등록한다. 서버가 UTC이면 cron `0 21 * * *`.
스케줄러가 없으면 `integrations.news_enabled = true`일 때 오늘 06:00 이후 첫 접속에서 한 번 자동 수집한다.

## 3. 다른 화면 담당자와의 약속

- **게시물 상세 열기 (SCR-05 차유진, SCR-01 편성훈)**
  `from sea_info.scr06_post_detail import open_post_detail` →
  `open_post_detail(post["id"], return_page="pages/community.py", return_label="커뮤니티")`.
  돌아가기를 누르면 그 페이지로 가고 게시판 탭 상태를 되돌린다.
- **목록의 숨김·비공개 걸러내기**: `scr06_store.list_visible_observations(user, role)`을 쓰면 신고로 숨겨진 글이 자동으로 빠진다.
  (home, community에는 같은 조건을 직접 넣어 두었다.)
- **수족관 자동 추가 (SCR-04 김바로, SCR-16 이정민)**: 따로 호출할 필요 없다.
  `observations`에 글이 INSERT되면 DB 트리거(`trg_scr08_obs_insert`)가 같은 트랜잭션에서 수족관·관찰 기록을 만든다.
  종이 비어 있으면 `미확인`으로 등록된다. SCR-04 입력 목록에 `미확인` 항목을 넣어야 미확인 게시가 가능하다.
- **도감 상세 (SCR-09 편성훈)**: `sea_info/scr09_dex_detail.py`에 `render_species_detail(species: str)`를 만들면 SCR-08이 자동으로 그 함수를 부른다.
  사진 공개 철회는 `scr08_store.make_photos_private()`를 쓰면 사진을 지우지 않고 본인에게만 보이게 한다.
- **작성자 공개 프로필 (SCR-07 차유진)**: `pages/author_profile.py`가 있으면 작성자 이름을 눌렀을 때 그쪽으로 이동한다(`st.session_state["public_profile_author"]`에 작성자가 들어 있다). 없으면 상세 화면 안에 요약 패널을 보여 준다.
- **운영자 화면 (ADM-01/03 김바로)**: 신고 대기 목록은 `scr06_store.report_queue()`, 뉴스 출처 상태는 `scr13_store.list_sources()`, 수집 이력은 `scr13_store.recent_runs()`.

## 6. 확인하지 못한 것 · 한계

- **뉴스 출처 (2026-11-08 확인)**: 처음 넣은 정책브리핑 RSS는 2026-07-01에 제공이 중단되어 열리지 않는다(사이트 공지). 기본 출처를 한국수산경제 전체기사 RSS(`http://www.fisheco.com/rss/allArticle.xml`)로 바꿨다. 브라우저로 열어 RSS 2.0 형식과 2026-11-06 기사를 확인했다. 매체 출처는 운영자가 "이용 조건 확인함"을 켜야 수집한다(기본 꺼짐). 종민 님이 지정한 기사목록 주소 2개도 기본 출처로 넣었다: 현대해양 "연근해 어업"(`.../news/articleList.html?sc_sub_section_code=S2N9&view_type=sm`), 뉴스펭귄 "우리고장 멸종위기종"(`.../S2N122`). 이 둘은 RSS가 아니라 웹 목록이라 수집기에 `parse_article_list`를 추가했다(제목·링크·요약·시각을 읽음). 브라우저에서 두 화면의 HTML 구조를 확인해 시험 자료로 썼지만, 앱이 서버에 직접 접속해 읽어 오는 것은 PC에서 `--check`로 확인해야 한다. 화면 구조가 바뀌면 "기사 목록을 찾지 못했습니다"로 실패 기록이 남는다. 뉴스펭귄 구역은 육상 생물도 포함한다. 해양수산부 보도자료는 게시판 화면만 있고 RSS를 찾지 못했다. 공공데이터포털 API 등 공공기관 출처는 팀이 정한다.
- **Gemini 요약**: 가짜 응답으로만 시험했다. 실제 호출은 `ai.provider = "gemini"`와 `GEMINI_API_KEY`가 있을 때 켜지며, 아직 한 번도 실제로 호출해 보지 않았다. 실패하면 원문 발췌 요약으로 대체된다.
- **비회원 조회 중복**: 쿠키 없이 접속 정보(IP+브라우저)로 근사한다. 같은 사람이 다른 환경에서 보면 따로 집계된다.
- **브라우저 화면**: Streamlit AppTest로 전 페이지·3개 역할을 돌렸고 오류는 없었다. 실제 브라우저 캡처는 PC에서 확인이 필요하다.
- **FastAPI**: 아직 없다. `*_store.py` 함수가 화면과 분리되어 있어 엔드포인트 본문으로 그대로 옮길 수 있다. 강사님 요구와 맞추는 방향은 팀 결정이 필요하다.
- 원본 `store.withdraw_species_photos`는 사진 자체를 삭제한다. 명세(철회 시 본인만 보기)와 다르므로 `make_photos_private`로 바꿀 것.
- 원본 `create_observation`은 사진 공개 동의가 없으면 사진을 저장하지 않는다. 그래서 "나만 보는 사진"은 동의를 철회한 경우에만 생긴다.
